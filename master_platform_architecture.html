Master flows

Inputs and outputs are designed as traceable end-to-end journeys.

Candidate Lifecycle

Registration → Screening → Applicant → Assessment → Candidate Activation → Enrollment → Learning → Exams → Evidence → Requirements → Matching → Outcome

Kids Explorer Lifecycle

Passport → Level → Season → Mission → Stamp → Badge → Certificate → Content/Product Experience

Assessment & Exam Lifecycle

Blueprint → Question Bank → Version → Eligibility → Session/Attempt → Integrity → Scoring → Result → Evidence → Credential/Retake

Airline Recruitment Lifecycle

Employer → Role → Requirements → Campaign → Matching → Review → Shortlist → Interview → Offer/Hiring Outcome

Candidate Dossier Lifecycle

Identity → Entry Profile → Assessment → Development → Training → Exams → Credentials → Requirements → Readiness → Controlled Release

Requirement Evaluation Lifecycle

Requirement → Evidence Lookup → Rule Evaluation → Gap → Decision → Trace → Re-evaluate

Role-based portals

The same platform can later expose different controlled views without duplicating the core data.

Platform AdministratorOperations StaffCandidate / LearnerParent / GuardianInstructorExaminer / AssessorAirline / EmployerInstitutionPublic Visitor
Freeze Rule: Any new module, screen, engine, dashboard or report must be registered under one of the six domains and mapped to Input → Process → Evidence → Decision → Output. Candidate, employer, Kids and learning data must not be duplicated into isolated systems.
